# HANDOFF — dcap-secret-scanner (Rust) / перенос на другой комп

Этот файл — полный контекст для продолжения работы `opencode` на ДРУГОМ компьютере.
Прочитай его целиком перед продолжением. Ниже всё, что нужно знать и что делать дальше.

================================================================================
0. КРАТКАЯ СУТЬ ПРОЕКТА
================================================================================
Сканер папок на секреты (пароли, SSH-ключи, токены, строки подключения и т.д.).
Русскоязычный, потоковый, с большим набором regex-правил под стек
.NET/Java/Kafka/Redis/k8s/AD. Есть ДВЕ реализации:

- `scan_folder.py` — эталон на Python (строго stdlib, потоки, префильтр, деадлок-фикс
  на `collections.deque`). Есть `--presidio` (NLP), в Rust-версии его нет.
- Rust-порт `dcap-scan` — цель: полностью аналогичный, быстрее, собран в бинарник
  и в Docker-образ с поддержкой маунта СЕТЕВОГО ДИСКА (SMB) внутри контейнера.

Пользователь переносит проект на другой комп. Задача: чтобы opencode на новом компе
мог продолжить работу (дособрать Docker, залить на GitHub, дальше развивать).

4. ПЛАН ПРОДОЛЖЕНИЯ НА НОВОМ КОМПЕ (чтобы открыть, скопировать, продолжить)
================================================================================
1) Скопировать ВСЁ содержимое E:\projects\dcap-secret-scanner-rust на новый комп
   (например в ту же папку). Скопировать сам этот HANDOFF-файл тоже.

2) Проверить окружение на новом компе:
   - rustup show (какие тулчейны). Если нет gnu с mingw — см. раздел 5 по установке.
   - где mingw/gcc. Прописать PATH к mingw64\bin.
   - Проверить сборку:
       $env:PATH = "<путь к mingw64>\bin;" + $env:PATH
       cargo +stable-x86_64-pc-windows-gnu build --release
   - Быстрый смоук-тест на локальной маленькой папке: dcap-scan <папка> <лог> 10.

3) Собрать Docker:
       docker build -t dcap-scan .
   (в папке проекта). Это возобновит прерванный билд. Образ: alpine с cifs-utils.
   Примечание: образ собирается ЛОКАЛЬНО билдером rust:alpine — сетевой доступ на
   сборку крейтов нужен. На новом компе проверить, что cargo/docker могут качать с crates.io.

4) Протестировать SMB-маунт в контейнере (главная новая фича):
       docker run --rm --privileged `
         -e SMB_SHARE="//mynas/MainStorage" `
         -e SMB_USER="mynas\<пользователь>" `
         -e SMB_PASS="<пароль>" `
         -e "SMB_OPTS=,vers=3.0,noperm,cache=none" `
         -v "${PWD}\logs:/logs" `
         dcap-scan /mnt/share /logs 10
   (пароль на другом компе подставить свой; можно через SMB_PASS_FILE и bind-файл).
   Ожидание: «Mounting SMB share ...», затем сканирование, лог в logs/.

5) git: в папке проекта выполнить
       git init
       git add .
       git commit -m "Rust scanner: dcap-scan + Docker (SMB mount)"
   (ПРОВЕРИТЬ .gitignore — туда не должны попасть target, .env, ключи, логи!)

6) GitHub (см. раздел 6 — инструкция пользователю). Дальше по желанию:
   - дедуп двойных находок CRED_PASSWORD+CRED_GENERIC_SECRET (вопрос к пользователю),
   - проверка full bench на новом компе для сверки цифр.

B) В PowerShell в папке проекта (уже git init + commit, см. п.4):
   git remote add origin https://github.com/<LOGIN>/dcap-secret-scanner-rust.git
   git branch -M main
   git push -u origin main

   (если Windows спросит логин/пароль — всплывёт окно git credential manager;
    пароль от GitHub в 2026 году — это Personal Access Token, не пароль от сайта!)
C) Либо через GitHub CLI (если установлен и gh auth login):
   gh repo create dcap-secret-scanner-rust --private --source . --push --remote origin

D) Если аккаунт публичный и нужно приватное — выбрать Private. Secrets в репо
   НЕ добавлять. В .gitignore уже закрыты .env/ключи/пароли — перед push проверить
   `git status` и убедиться, что в репо нет ничего секретного.

7. ИЗВЕСТНЫЕ ПОДВОДНЫЕ КАМНИ / ПРИМЕЧАНИЯ
================================================================================
- MSVC-линкер на этой машине отсутствует — НЕ пытаться собирать под
  x86_64-pc-windows-msvc (будет «link.exe not found»). Всегда gnu-тулчейн.
- Цифры бенчей на новом компе зависят от шары Z:; для «эталонных» чисел сперва
  перегенерировать тестовые деревья.
- В Cargo.toml zip 2.4.2 (не 8.x), crates скачивались с crates.io индексом; на новом
  компе cargo обновит Cargo.lock при необходимости — держать `--locked` в докер-
  билде, чтобы не сломать версии.
- entrypoint.sh требует, чтобы образ имел cifs-utils. Если NAS только SMB2/3 — опция
  `vers=3.0`; для старых SMB1 не нужно. При ошибке маунта проверить SMB_USER/домен.
- Лог сканера с отметкой времени: имя файла scan_<YYYYmmdd_HHMMSS>.log автоматически.
- Тестовые синтетики на старом компе лежали в e:\Temp\opencode\ (re_test.py,
  test_new_patterns.py, gen_bench.py, gen_office_tests.py, папка pat_tests).
  При желании скопировать их на новый комп для перепроверки.
